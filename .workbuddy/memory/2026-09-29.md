## 高位生态「监管池·全生命周期」块优化（MonitorHeatmap.vue，用户截图标注）
- **真问题·累计涨幅曲线跨股票不可比**：`linePoints` 对每条 series 各自算 min/max（都从 0 起），于是「+1.9%」和「−7.6%」在图上画成一样的高低，标题承诺的「跌破 0 轴」根本没有 0 轴。改为所有线共用一套纵轴（合并全部点、强制含 0，`chartScale`/`yOf`/`zeroY`），画出 0 轴虚线，左侧给 max/0/min 三个刻度（0% 按 `zeroY%` 绝对定位，不是永远居中）。x 轴同样统一按「监管期第几天」对齐（`chartMaxLen`），D+3 的票不再和 D+10 的票一样宽，且与上表列天然对齐。每行一条小图改成一图多线 + 右侧图例带末值（末值按涨红跌绿）。
- **单点票在图上消失**：只走了 D+1 的票（新华锦）单点连不成 polyline → 图上什么都没。补「每天一个点」标记，用零长 `<line>` + `stroke-linecap="round"` 当圆点。**不能用 `<circle>`**：`preserveAspectRatio="none"` 会把它压成扁椭圆；圆头帽的 stroke 宽度吃 `vector-effect="non-scaling-stroke"`，不受拉伸影响。
- **纵轴刻度错位 ~18px**：`.mm-scale` 原来按整个图表区（128px，含底部 D+1 刻度行）定位，而 svg 只占 110px → 底部「−7.6%」比线低十几像素。改为三者都锁 110px（svg 110 + xaxis 18，右侧图例也 110 居中）。
- 脚注补票名（`.why-name` + 「状态依据」小标题）：脚注与上表按顺序对应，十几只票时靠顺序猜是哪只太费劲。

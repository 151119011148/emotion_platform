## 候选池表格列宽优化（WaveRiderView.vue）—— 诊断靠截图像素分析

- 当前模型读不了图，改用 PIL 对截图做像素取证：卡片横跨 x28..2272（图宽 2280），
  表格内容 x46..2246 铺满整卡、底部无横向滚动条 → 不是"太宽被截断"，是**被拉宽**。
- 根因（已查 element-plus `table-layout.mjs` 源码证实）：
  `flexColumns`（没写 `width`、只有 `min-width` 的列）按 **minWidth 比例**瓜分富余宽度：
  `realWidth = minWidth + floor(minWidth * (bodyWidth - bodyMinWidth) / ΣminWidth)`，
  第一个弹性列再吃掉余下的取整差额。
  宽屏（容器 ≈1764 CSS px）下「名称 150 → **340px**」「题材 240 → **544px**」，
  而内容只占 130~200px → 大片空白。**bodyWidth = table 元素的 clientWidth**，所以给包一层
  `max-width` 的外层 div 就能封顶。
- 改法：表格外包 `<div class="tbl">` + `.tbl{max-width:1400px}`（scoped 样式），
  名称 min-width 150→165、题材 240→235。
  → 1400 宽下：名称 215、题材 305；窗口再宽也只是右侧留白变多，列不再膨胀。
  最小可容宽度 880(固定列)+165+235 = **1280**（原 1270，基本不变，窄屏行为不受影响）。
- 校验：`@vue/compiler-sfc` parse+compileScript+compileTemplate 通过。
- 本地已起（前端 5173 / 后端 8080，`unset SERVER__PORT`）。vite 下发的模板里
  `min-width` = 165/235、样式模块 `.tbl[data-v-b4e676f2]{max-width:1400px}` 均已确认生效。
- 09-29 候选 8 只**全部带 score_breakdown**（昨晚那次被打断的本地重跑其实已落库）。

## 卖出日记错日（用户报障：今天点的清仓，卖出日却显示 09-28）

- 现象：持仓与台账页「标的全生命周期」里五方光电/襄阳轴承 卖出日=2026-09-28，用户是 09-30 当天点的清仓。
- 根因：该页「当前持仓」表就地编辑的状态下拉写的是**快照日**的行，而快照日=台账最近有记录的一天（09-28；09-30 还没录过任何行）。用户今天把 09-28 的两行翻成「今日清仓」→ savePositions(date=09-28) → 清仓记到了历史日。
- 修法（PositionsView.vue，纯前端）：状态被翻成「今日清仓」且该行 tradeDate < 今天时，保存拆成两笔——旧快照日该行恢复「持仓中」（清仓属性 sellPrice/sellQty/delayDays/disciplineScore 还原为原值，其余编辑保留），今天新建「今日清仓」行（今天已有同代码行则并入不重复建）。pendingMoves computed 在保存条上实时提示。更正历史某天的台账仍走那天的复盘页。vite build 通过。

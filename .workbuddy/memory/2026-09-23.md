## 节点命名口径：禁反义定义，改按两轴命名
- 用户指出「普通节点」不专业。根因：它是**反义定义**（只说它不是什么），且每新增一个 node_type 词义就要变一次。
- 定案（已写入 PRD §2 术语 + 命名约定 callout）：
  - **类型轴**：五个具体 node_type：start 1.0 / switch 0.8 / diverge 0.6 / space_break_next 0.9 / space_break 0(观察)。**识别不出来就是 null，UI 显示「未识别」**，绝不回填「普通」。
  - **来源轴**（正交，不参与分类）：`人工节点 manual` → `t_node_event`；`策略节点 auto` → `t_node_detect`。两表互不写入，别混为一谈。
  - 需要统称时按**方向**而非否定：**周期节点 phase node**（启动/分歧/切换，横向=周期第几拍）**vs 空间节点 space node**（破局日/破局次日，纵向=天花板在哪）。
  - 淘汰候选：常规（换汤不换药）、题材节点（覆盖不了分歧日——分歧按高位股赚钱效应定义不锚题材）、情绪节点（撞「情绪温度」）、状态节点（撞 `status` 字段的待验证/有效/失效）。
